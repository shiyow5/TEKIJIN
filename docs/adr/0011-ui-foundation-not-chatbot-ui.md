# ADR-0011: フロント UI の土台は自前設計を維持し、chatbot-ui は採用しない

- ステータス: 承認
- 日付: 2026-08-27
- 決定者: A チーム（UI/UX 壁打ちの結論）
- 関連: エピック #474（知識が生まれる瞬間を見せる体験）/ 子Issue #475–#480 / `docs/ux/knowledge-birth-prototype.html`

## 背景

UI/UX を改善するにあたり、OSS の [mckaywrigley/chatbot-ui](https://github.com/mckaywrigley/chatbot-ui) を
土台に採用して改良する案を検討した。フロントの見た目・体験を早く底上げしたい、という動機。

## 決定

**chatbot-ui は採用しない。** 既存の Next.js フロントを維持し、必要なチャット/カード UI コンポーネントだけを
自前設計する（必要ならヘッドレス部品を部分採用）。差別化は Screen 03/04/05 の**知識化の情報設計**に投資する。

## 理由

1. **汎用 LLM チャットクライアントであり、ナレッジ管理の UI ではない。** TEKIJIN の差別化点はチャットではなく
   「暗黙知の形式知化」（[[tekijin-product-direction]]）。土台の前提がプロダクトの主軸とズレる。
2. **Supabase に深く結合した大きめのコードベースを丸ごと背負う。** 本リポジトリは FastAPI + PostgreSQL +
   Next.js の自前構成で、Supabase 前提ではない。移植コストと将来のメンテ負債が見合わない。
3. **OSS をそのまま使っても UX の課題（情報設計）は解決しない。** 他フォークと同じ見た目になるだけ。
   本プロダクトの UX 課題は、チャット部品ではなく「知識が生まれる瞬間をどう見せるか」の情報設計にある。

## 影響

- フロントの土台変更は行わない。UI 改善は #474 の子Issue（画面単位）で、既存フロントの上に実装する。
- 参考プロトタイプ `docs/ux/knowledge-birth-prototype.html` を一次資料とし、各画面の実装がこれに沿うか照合する。

## 却下した代替案

- **chatbot-ui をフォークして改良**: 上記理由で却下。
- **土台を丸ごと別 OSS へ**: 同じ「土台がプロダクトとズレる」問題を抱えるため見送り。必要な部品は個別採用に留める。
