# ADR-0006: C6 スコアラーの R@3 天井は「証拠カバレッジ」であり、パラメータ調整では上がらない

- ステータス: 承認
- 日付: 2026-08-25
- 決定者: A チーム（研究・実測に基づく）

## 背景

gold トピックを与えた層2 person Recall@3 が実埋め込みで **~0.80** で頭打ちし、spec §7 の目標 0.90 に届かない。「C6 の線形重み・飽和・base_score を調律すれば上がるのか？」を、実 Nemotron 埋め込み＋本番同型の候補集合で厳密に測った（`scripts/research_c6_sweep.py`・DGX throwaway pgvector）。

## 選択肢

- 案A: C6 のパラメータ（`Weights` の線形係数・`edge_weight` の飽和 `scale`・`BASE_SCORE_*`）を調律して R@3 を上げる。
- 案B: スコア関数の形（sum→max 等）を作り替える。
- 案C: パラメータでは上がらないと結論し、真のレバー（証拠カバレッジ＝データ）へ資源を振る。

## 決定

**案C**。実測で以下が確定した（62 person-gold 行・候補プールは全件 top_k=10）：

- **候補プール recall = 0.952**（gold 専門家はほぼプールに居る）→ retrieval/プールは天井でない。
- **R@3 はパラメータに完全非依存**：`Weights` の全振り・`edge_weight` の `scale`(1→8)・`BASE_SCORE_*` の
  極端なリバランス（案件 lead 0.8→1.5）でも **R@3(primary)=0.7957 / R@3(alt)=0.8182 が不変**。
  スコア値自体は変化する（例 q1 の候補 35: 0.65→0.62）が、**強候補の相対順位が変わらない**（順位は
  証拠のボリュームで決まり、リバランスは全候補を比例スケールするだけで再順序化しない）。
- **取りこぼしの内訳**：証拠ゼロ（=行動痕跡皆無・データ欠損）は **2件のみ**。残り **27件は gold が
  topic 証拠を持つのに、より証拠豊富な非 gold に正当に負ける**。alt(回答由来) R@3=0.818 > primary(案件由来)
  0.796 も、スコアラーが可視証拠でランクしている（案件に居ただけの薄い証拠より、答えた実績が効く）ことを示す。

したがって **R@3~0.80 は C6 の原理的天井**であり、パラメータのバグでも調律不足でもない。案件由来の
gold（薄い証拠）と「証拠が厚い人」ランキングの**グラウンドトゥルースの緊張**が本質。案B（max 型等）は
「1件の強い証拠が5件の中程度に勝つ」という不自然な設計で、overfitting リスクが高く採らない。

## 影響

- **C6 のパラメータ調律を推薦精度向上の手段として追わない**（#63/#85 系の重み探索は打ち止め）。既定値を維持。
- **真のレバーは「証拠カバレッジ（データ）」**：人ごとのトピック活動（answers / projects / daily_reports）を
  実態に近く厚くすると、薄い gold に可視証拠が付き R@3 が上がりうる。→ **#326（営業日報を SPR 訪問
  フォーマットで実態化）** がこの領域に直結。合成 fixture の証拠カバレッジ拡充が次の主レバー。
- spec §7 の目標 0.90 は「スコアラーを詰める」ことでは到達せず、**データ側（証拠密度）と gold 定義**の
  問題として扱う。層別・alt gold での監視は継続（[[tekijin-eval-basis]]）。
- 恒久ハーネス `scripts/research_c6_sweep.py`（候補プール recall 診断＋重み/scale/base_score スイープ＋
  取りこぼしの証拠有無内訳）を残す。コーパス/埋め込みが変わったら再実行して天井を測り直す。
- 関連: #222（`edge_weight` 飽和で確信度ラベルが張り付く）も同根＝飽和は確信度表示の問題であって
  ランキングの律速ではないことが本 ADR で確認された。
