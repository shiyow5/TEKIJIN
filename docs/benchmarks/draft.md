# C7 下書きの品質（Issue #91）

C7（依頼文の下書き）は **#61 でモデル選定を保留したまま、品質を一度も測っていなかった**。
層2 Recall@3 や経路正解率は測ってきたが、**デモで人が実際に読むのは下書き**なので、ここが最大の穴だった。

実施 2026-08-22。評価は `eval_person.json` の56件（L4 を除く）。
C7 の契約どおり、**検索した文書は渡さず**、質問文・選ばれた専門家のレコード（名前・部署・C6 の根拠）だけを渡す。
再現: `scripts/research_draft.py`（入力生成・根拠照合・ペア比較）と `scripts/research_llm.py --task draft|judge`。

## 1. 結論: C7 は **Qwen3.6-35B-A3B-NVFP4** を採る

| | **Qwen3.6-35B** | Swallow-30B |
|---|---|---|
| 根拠との照合で違反ゼロ | **56/56 (100%)** | 55/56 (98.2%) |
| 字数 中央 / 最大 | **186 / 239** | 550 / 1338 |
| 「200字程度」を守った率（400字以下） | **56/56** | 6/56 |
| 番号付きの依頼事項を勝手に足した率 | **0%** | 84%（平均 2.61 項目） |
| 未置換のプレースホルダ（〇〇/△△）が残った件数 | **0** | 35 |
| p50 レイテンシ | **1.38s** | 4.79s |

**ペア比較（LLM-as-judge）は判断材料にならなかった**（§3）。決め手は上の機械的な指標。

## 2. 根拠に基づいているか

下書きに出てくる固有名詞・数値を、**渡した情報全体**（質問文＋専門家のレコード）と照合する。

- 取り次ぎ先以外の**社員名**を出していないか
- 渡していない**商材名・資格名・拠点名**を書いていないか
- **金額・品番・割合**を作っていないか
- 宛名が取り次ぎ先になっているか

Qwen3.6 は 56件すべてで違反ゼロ。Swallow は1件（id 46）で **5つの違反**を同時に出した。

```
【背景】
- 同一品目（品番：XXXXX）に対し、東京拠点では¥1,200、大阪拠点では¥1,350と単価差が生じています。
```

**品番も金額も拠点も、一切渡していない。** 相談文は「同じ品目なのに拠点ごとに単価が違うと言われました」だけ。
実在の同僚に送る文面なので、これは他の違反より重い。

> 最初の測定では Qwen3.6 にも2件の「拠点名の作り話」を検出したが、**照合の誤りだった**。
> 拠点の制約は質問文に書かれており、モデルは引用しただけ。
> 根拠だけでなく**渡した情報全体**と突き合わせるよう直してある。

## 3. ペア比較は自己選好で潰れた

MT-Bench の作法にならい、**順序を入れ替えて2回聞き、一致した判定だけを勝敗に採る**形で測った。
さらに**自己選好バイアスを見るために審判を2モデルで回した**。

| 審判 | 決着 | Qwen3.6 の勝ち | Swallow の勝ち | 先に出したほうを選んだ率 |
|---|---|---|---|---|
| Qwen3.6-35B | 49/56 | **48** | 1 | 0.53 |
| Swallow-30B | 45/56 | 1 | **44** | 0.40 |

**2つの審判はほぼ完全に食い違い、どちらも自分の出力を選んだ。**
位置バイアスは小さい（0.53 / 0.40）ので、順序の問題ではなく**自己選好**である。

**この構成では LLM-as-judge は信号にならない。** 審判に使える第3のモデルが無いか、
人手評価をしない限り、ペア比較で C7 を決めることはできない。
今回は機械的な指標（§1・§2）が十分に大きく開いているので、そちらで決めた。

## 4. 質的な違い

**Swallow は依頼を「作業指示」に変えてしまう。** 84%の下書きに番号付きの依頼事項が入る。

```
1. 交渉担当者ごとの過去の交渉実績を一覧化し、条件のばらつきを可視化してください。
2. 価格交渉の基準となる「価格交渉マニュアル」のドラフトを作成し、担当者全員が遵守できるようご指導いただけますでしょうか。
```

相談者は「整理の仕方を相談したい」としか言っていない。**マニュアル作成を依頼した覚えはない。**
取り次ぎ役が相手の作業を勝手に増やすのは、社内で人に頼む道具としては危うい。

Qwen3.6 は根拠を過度に具体化せず、相談内容をそのまま伝える。

```
佐々木様

お世話になっております。
システム画面のレスポンス遅延についてご相談を受けました。利用集中時間帯に画面が返ってこない現象があり、
調査の着手点についてご助言をいただけないでしょうか。
（…）
```

## 5. 限界

1. **`asker`（相談者）を渡していない。** 評価セットに相談者IDが無いため。
   C7 の契約には `asker` があるので、これはハーネスの簡略化。
   **プレースホルダの差（Swallow 35件 vs Qwen3.6 0件）はこの簡略化に起因する**。
   Swallow は `〇〇部の△△です` と穴を残し、Qwen3.6 は自己紹介を省く。
   相談者を渡せばどちらも埋めるはずなので、**この項目だけは優劣の証拠として弱い**
2. **`missing`（不足スロット）を空で渡している。** 「渡していないのに補足を作文しないか」を見る側に寄せた。
   逆向き（渡した不足スロットを落とさないか）は測れていない
3. **根拠照合は固有名詞と数値のパターン照合**。
   「もっともらしいが根拠の無い一般論」は検出できない。§4 の作業指示化がまさにそれで、
   機械では拾えず目視で見つけた
4. **ペア比較は使えなかった**（§3）。品質の順序づけは機械的な指標に依存している

個別値は `ablation/draft_*.json` / `ablation/ground_*.json` / `ablation/judge_*.json`。
